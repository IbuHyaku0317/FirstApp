# Android実機テスト項目書

## 1. 目的

本書は、Android実機で「一年後の記憶」の主要機能、端末固有の挙動、異常系を確認するための手順書である。
機能ごとの確認結果を同じ基準で残し、Google Play公開前の完了判定に使用する。

関連文書：

- [モバイルフロントエンド設計](./MOBILE_FRONTEND_DESIGN.md)
- [バックエンド設計](./BACKEND_DESIGN.md)
- [技術スタック・環境](./TECH_STACK.md)

## 2. 判定方法

| 項目 | 定義 |
| --- | --- |
| 合格 | 期待結果を満たし、継続利用を妨げる表示崩れや警告がない |
| 不合格 | 期待結果と異なる、操作不能、クラッシュ、データ不整合がある |
| 保留 | 課金接続など、未実装または外部準備待ちで確認できない |
| 未実施 | まだ確認していない |

優先度は次のとおりとする。

- `P0`：公開前に必ず合格が必要。認証、データ保護、投稿、復旧不能な問題。
- `P1`：主要な利用体験。原則として公開前に合格が必要。
- `P2`：細かな表示、操作感、将来改善候補。

## 4. 事前準備

### 4.1 必要なアカウント

| アカウント | 用途 |
| --- | --- |
| 無料会員A | 通常の投稿、Premium導線、開発用動画投稿 |
| 無料会員B | 他ユーザーの投稿を取得できないことの確認 |
| 新規登録用メール | サインアップと記念日初期設定の確認 |
| Premium会員 | Google Play Billing接続後に作成。それまでは保留 |

すべてテスト専用のメールアドレスとメディアを使用し、個人情報を含む実データは使用しない。

### 4.2 テストメディア

| ファイル | 条件 | 用途 |
| --- | --- | --- |
| 横長JPEG | 5MB未満 | 通常写真投稿 |
| 縦長JPEG | 5MB未満 | 回転・縦横比確認 |
| PNG | 5MB未満 | 対応形式確認 |
| WebP | 5MB未満 | 対応形式確認 |
| 短いMP4 | 10秒程度、100MB未満 | 開発用動画投稿・再生 |
| 上限付近MP4 | 55～60秒、100MB未満 | 動画上限内確認 |
| 長すぎるMP4 | 60秒超 | 動画時間エラー確認 |
| 大きすぎるファイル | 100MB超 | 容量エラー確認 |
| 非対応ファイル | PDFなど | 選択・API検証確認 |

### 4.3 起動条件

1. Docker Desktopを起動する。
2. PostgreSQLとAPIを起動する。
3. Android実機とPCを同一ネットワークへ接続する。
4. PCのLAN内IPを確認し、API URLへ設定する。
5. Expo GoまたはDevelopment Buildでアプリを開く。

```powershell
cd C:\Users\zardi\FirstApp\hyakutaApp
docker compose up -d
dotnet run --project src/api/Memory.Api --urls http://0.0.0.0:5080
```

別のPowerShellで、`<PCのLAN内IP>` を実際の値へ置き換える。

```powershell
cd C:\Users\zardi\FirstApp\hyakutaApp\src\mobile
$env:EXPO_PUBLIC_API_URL="http://<PCのLAN内IP>:5080/api/v1"
npx.cmd expo start --lan --clear
```

## 19. 公開可否の基準

Android版を公開候補とするには、以下をすべて満たす必要がある。

- `P0`がすべて合格している。ただし明示的な未実装機能は保留理由と公開範囲を記録する。
- `P1`に継続利用を妨げる不合格がない。
- クラッシュ、データ消失、他ユーザー情報の表示が0件である。
- 写真投稿と一年後の解禁を、少なくとも1台のAndroid実機で完走している。
- 開発用機能がProductionビルドとProduction APIで無効である。
- Google Play Billing接続後は、購入・復元・解約・返金の追加テストを完了している。
- 不合格項目には不具合番号、対応方針、再テスト結果が記録されている。
