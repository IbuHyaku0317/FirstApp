# モバイルフロントエンド設計書

## 1. 文書の目的

本書は、iPhone（iOS）およびAndroid向けアプリのフロントエンド設計を定義する。
現在のWeb版の実装構造を説明するものではなく、確定したプロダクト方針を基にした新しいモバイルアプリの設計である。

## 2. プロダクトの基本体験

このアプリは「今日の思い出を保存し、1年後に開くタイムカプセル日記」である。

- 投稿した内容は、投稿直後から10分間だけ取り消せる。
- 取り消し可能時間を過ぎると、1年後の解禁日まで本文とメディアを閲覧できない。
- 解禁後は、その日限りではなく常にカレンダーから閲覧できる。
- 通常日は1日1件まで投稿できる。
- 設定中の記念日は1日2件まで投稿できる。
- 1件の投稿には、写真または動画のいずれか1ファイルとメッセージを登録できる。
- 無料会員は写真のみ、有料会員は写真または動画を登録できる。
- 動画は最大60秒かつ100MBとする。
- 他ユーザーとの共有は初期リリースの対象外とし、将来TODOとする。

## 3. 対象プラットフォーム

- iOS：App Store配信を想定
- Android：Google Play配信を想定
- スマートフォンの縦向きを初期リリースの主対象とする。
- タブレットはレイアウト崩れを防ぐが、専用UI最適化は将来対応とする。
- iOSとAndroidはReact Nativeの共通コードを基本とし、OS固有機能だけを分離する。

## 4. 画面構成

すべての画面のセーフエリア内右上に、日本語／英語の共通言語切り替えを常設する。
未ログイン時は現在の認証操作に使用する表示言語を切り替え、ログイン後は切り替えと同時にプロフィールへ保存して全画面へ反映する。
保存に失敗した場合は直前の言語へ戻し、エラーを通知する。

### 4.1 認証前

| 画面 | 目的 | 主な機能 |
| --- | --- | --- |
| 起動画面 | セッション復元 | トークン更新、初回遷移判定 |
| サインアップ | アカウント作成 | メールアドレス、パスワード、表示名、言語、タイムゾーン |
| ログイン | 認証 | メールアドレス、パスワード |
| パスワード再設定 | 認証情報の復旧 | 再設定メール送信、パスワード更新 |
| 記念日設定 | 初回設定 | 記念日名、月日、スキップ |

サインアップ成功後は、カレンダーではなく記念日設定画面へ遷移する。記念日は後から設定できるようにスキップを許可する。

### 4.2 認証後のメインタブ

下部タブは以下の3つに限定する。

1. カレンダー
2. 投稿
3. プロフィール

初期表示はカレンダーとする。

### 4.3 カレンダー画面

#### 月表示

- 解禁済みの投稿がある日にはサムネイルまたはマーカーを表示する。
- 通常日は最大1件、解禁済みの記念日は最大2件を表示できる。
- 未解禁投稿の本文、サムネイル、メディア種別は表示しない。
- 今日投稿済みであることは、内容を見せず「保存済み」として表示してよい。
- 月移動は左右スワイプと前月・翌月ボタンの両方に対応する。
- 最初に開いた月はユーザーの現地年月とする。

#### 日別詳細

- 選択日の解禁済み投稿を投稿順に表示する。
- 日付選択直後は、カレンダーの下に投稿ごとの写真サムネイルまたは動画の先頭フレームを表示する。動画はここでは自動再生せず、動画であることを示すアイコンを重ねる。
- プレビューを押すと1投稿単位の詳細画面へ遷移し、写真または動画、メッセージ、投稿時刻を表示する。
- 詳細画面の戻る操作では、遷移前と同じ年月および日付を選択したカレンダーへ戻る。
- 投稿時刻はAPIのUTC日時をユーザー設定のタイムゾーンへ変換して表示する。
- 写真は拡大表示、動画はユーザー操作で再生する。
- 詳細画面から、解禁済みの写真または動画を端末の写真ライブラリへ保存できる。
- 記念日の2件は、最初に投稿したもの、次に投稿したものの順で表示する。
- 変更前の記念日で、解禁前に2件目が非表示対象となった場合は1件目だけを表示する。
- 一度解禁されてから記念日が変更された投稿は、2件とも表示を維持する。

#### 「1年前の今日」

- 今日解禁された投稿がある場合、カレンダー上部に案内を表示する。
- 通知から起動した場合は該当日の日別詳細を開く。
- 2月29日の投稿は、うるう年でない翌年には2月28日に解禁する。

### 4.4 投稿画面

#### 入力項目

- 写真または動画
- メッセージ（任意、最大2,000文字）
- 投稿対象日は端末入力させず、APIがユーザーのタイムゾーンから決定する。

#### 投稿可能数

- 通常日：1件
- 現在設定中の記念日：2件
- 無料会員：写真のみ。動画の選択肢は非表示にせず、鍵付きの非活性風表示と「Premium限定」を明記する。
- 有料会員：写真または動画。ただし1件に両方は添付できない。
- 当日の残り投稿数を画面に表示する。

無料会員が動画の選択肢を押した場合は、Premiumで利用できる動画の上限をダイアログで説明する。
ダイアログからPremiumプラン画面へ遷移できるようにし、戻る操作では入力途中の投稿画面へ戻す。
ストア課金の接続前は購入準備中であることを明示し、料金が発生する操作は提供しない。

#### 送信フロー

1. メディアを選択または撮影する。
2. 選択した写真または動画を投稿画面内に表示し、動画は再生・一時停止・シーク・全画面表示で内容を確認できるようにする。
3. 動画の場合は長さと容量を端末側でも事前検証する。
4. メッセージを入力する。
5. 「1年後まで見られなくなる」ことを確認ダイアログで案内する。
6. アップロード進捗を表示する。
7. APIの登録成功後、10分間の取り消し期限を表示する。
8. 10分経過後は内容を画面および端末キャッシュから除去する。

端末側の検証は操作性向上のためであり、最終的な投稿可否は必ずAPIの結果に従う。

#### 取り消し

- 登録完了から10分以内に限り取り消しボタンを表示する。
- 残り時間は表示するが、端末時計だけで可否を判断しない。
- APIが返した `cancelableUntil` を表示に使い、取り消し要求時にAPIが再判定する。
- 取り消し後は当日の投稿枠を再利用できる。

### 4.5 プロフィール画面

- 表示名
- メールアドレス
- 言語（日本語／英語。全画面共通の右上操作から即時変更）
- タイムゾーン
- 会員種別と有料プラン管理への導線
- 現在の記念日名と月日
- 記念日の次回変更可能日
- ログアウト
- アカウント削除

#### 記念日の変更

- 初回設定および前回変更から14日経過後に変更できる。
- ユーザーの現地日付が現在の記念日当日の場合は変更できない。
- 新しい記念日に当日の日付を指定することもできない。
- 変更は保存完了直後から有効とする。
- 変更前に解禁済みの記念日投稿は2件表示を維持する。
- 変更前に未解禁の記念日投稿は、解禁時に最初の1件だけ表示する。
- 影響を受ける未解禁の2件目が存在する場合、その件数を確認ダイアログに表示する。
- 非表示対象となる2件目は削除されないことを説明する。

## 6. Atomic Design

React Nativeのコンポーネントは以下に分ける。

| 層 | 例 |
| --- | --- |
| Atoms | Button、Text、Icon、Input、Badge、Thumbnail |
| Molecules | FormField、LanguageSwitch、PostMarker、Countdown、MediaPicker |
| Organisms | CalendarGrid、PostComposer、AnniversaryForm、ProfileSummary |
| Templates | AuthTemplate、MainTabTemplate、CalendarTemplate、FormTemplate |
| Screens | CalendarScreen、CreatePostScreen、ProfileScreenなど |

AtomsとMoleculesにはAPI通信や画面遷移を持たせない。サーバー状態は画面または専用hookから取得する。

## 7. 状態管理

| 状態 | 管理方法 |
| --- | --- |
| APIのサーバー状態 | TanStack Query |
| 認証セッション | Auth Provider＋SecureStore |
| 言語・テーマなど | 軽量なアプリ設定Store |
| 投稿フォーム | React Hook Form |
| 一時的な画面状態 | Reactローカルstate |

- アクセストークンをAsyncStorageへ平文保存しない。
- リフレッシュトークンはiOS Keychain／Android Keystoreを利用するSecureStoreへ保存する。
- 未解禁投稿の本文・メディアURLを永続キャッシュしない。
- ログアウト時は認証情報とユーザー固有キャッシュを消去する。

## 8. API通信

- HTTPSのみを使用する。
- `Authorization: Bearer` でアクセストークンを送信する。
- `Accept-Language` に現在の言語を設定する。
- タイムゾーンはプロフィールに登録し、IANA Time Zone IDを使用する。
- エラーはRFC 9457 Problem Detailsとして受け取る。
- 一覧取得はカーソル方式とする。
- メディアアップロードはAPIの指示に従い、将来的に署名付き直接アップロードへ移行可能にする。

## 9. 多言語対応

- 初期対応言語は日本語と英語。
- 言語切り替えは認証前、初回設定、メインタブ、各詳細画面を含む全画面で同じ位置に表示する。
- ログイン後の変更は即時に画面へ反映し、プロフィールの `preferredLanguage` と端末内セッションの両方へ保存する。
- 文字列をコンポーネントへ直接記述せず、翻訳キーで管理する。
- APIのエラーコードを基準にクライアント側で表示文言を選択し、未知のエラーだけProblem Detailsの文言を利用する。
- 日付、曜日、数値は端末言語ではなくアプリ内の選択言語で整形する。

## 10. アクセシビリティと操作性

- タップ領域は原則44pt以上とする。
- 色だけで投稿状態を表現しない。
- VoiceOverおよびTalkBack用のラベルを設定する。
- 文字サイズ拡大に対応する。
- アップロード失敗時に入力内容を保持し、安全に再試行できるようにする。
- 写真・動画へのアクセス拒否時は、OS設定への案内を表示する。

## 11. プッシュ通知

初期リリースでは以下を対象とする。

- 1年前の投稿が解禁された通知
- 投稿忘れ通知はユーザーが明示的に有効化した場合のみ送信する。

通知本文には、非公開期間中のメッセージや写真内容を含めない。

## 12. テスト方針

- 単体テスト：日付表示、フォーム検証、権限表示、翻訳キー
- コンポーネントテスト：カレンダー、投稿フォーム、記念日変更警告
- API結合テスト：認証更新、投稿枠超過、10分取消期限、多言語エラー
- E2E：サインアップから記念日設定、投稿、解禁済み表示まで
- 実機テスト：最新およびサポート対象最古のiOS／Android
- タイムゾーン変更、日付境界、2月29日、通信中断を重点的に確認する。

## 13. 初期リリース対象外

- 他ユーザーとの共有、フォロー、公開プロフィール
- 写真の撮影場所・端末の現在地の取得、保存、地図表示
- コメント、リアクション、ダイレクトメッセージ
- タブレット専用レイアウト
- 複数の記念日
- Web版との完全なUI共通化

位置情報は初期版では権限要求も行わない。ユーザー要望を確認したうえで、将来、投稿ごとの任意機能として再検討する。

## 14. 投稿体験の実装補足

- 選択中および解禁後の動画は `expo-video` のネイティブコントロールで再生し、全画面表示に対応する。
- 認証が必要なメディアURLにはアクセストークンをHTTPヘッダーで付与する。
- 端末への保存は、ユーザーが詳細画面の保存ボタンを押した時だけ `expo-media-library` の書き込み権限を要求する。他の写真・動画の読み取り権限およびメディアの位置情報は取得しない。
- 保存対象は認証付きで一時領域へダウンロードし、写真ライブラリへの保存完了後に一時ファイルを削除する。
- 投稿中は送信済み割合をプログレスバーで表示し、ユーザーがアップロードを中止できるようにする。
- 通信失敗時は選択メディアとメッセージを保持し、再送できるようにする。
- 10分取消は秒単位の残り時間を表示する。ただし最終的な取消可否はAPIが判定する。
- 開発ビルドのプロフィール画面に限り「開発用時計」を表示し、一年後の解禁状態を待たずに確認できるようにする。
- 開発用時計はUTCのISO 8601形式で入力し、実時間へ戻す操作も提供する。
- 開発用時計には現在の業務時刻を基準とする「1日後」「1か月後」「1年後」のショートカットを設ける。月末と2月29日は移動先の月末日に丸める。
- 取消カウントダウンはAPIの `serverNow` と端末時刻の差を補正して表示し、開発用時計を変更しても10分から正しく減算する。
- 開発ビルドでは無料会員の投稿画面に「開発用：動画を選ぶ」を追加し、課金接続前でも動画の選択・アップロード・一年後の再生を確認できるようにする。
- 開発用動画ボタンとPremium案内ボタンは分離し、無料会員向けの本来の導線も同時に確認できるようにする。
