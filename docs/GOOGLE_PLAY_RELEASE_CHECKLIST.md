# Google Play公開チェックリスト

最終確認日：2026-08-02

## 1. この文書の使い方

本書は、Android版「One Year Memory」をGoogle Playへ公開するまでの作業を、着手順に管理するためのチェックリストである。
Google Payではなく、Google Playでのアプリ公開とGoogle Play BillingによるPremium課金を対象とする。

記号：

- `[ ]` 未完了
- `[x]` 完了
- `[保留]` 外部準備または方針決定待ち
- `[対象外]` 今回の公開には含めない

担当：

- `ユーザー`：契約、本人確認、価格、法務判断、Play Console操作、最終承認
- `Codex`：実装、設定、ビルド、技術確認、文案作成
- `共同`：実機試験、申告内容確認、審査対応

- [ ] 実際の画面と一致するスマートフォン用スクリーンショットを用意する。`共同`
- [ ] カレンダー、写真投稿、Premium動画、プロフィールを中心に構成する。`共同`
- [ ] 日本語と英語でローカライズ画像が必要か決める。`ユーザー`
- [ ] 個人のメール、実在人物の写真、アクセストークンを画像へ含めない。`共同`
- [ ] 誇張、未実装機能、価格の不一致を画像へ含めない。`共同`
- [ ] 各画像の代替テキストを用意する。`共同`
- [対象外] 初回公開ではプロモーション動画を必須としない。

## 16. テストトラック

### 16.1 Internal testing

- [ ] Internal testingへ最初のAABを登録する。`ユーザー・Codex`
- [ ] 開発者と少人数のテスターを追加する。`ユーザー`
- [ ] Play Store経由でインストール・更新する。`共同`
- [ ] [Android実機テスト項目書](./ANDROID_DEVICE_TEST_PLAN.md)のP0を実行する。`共同`
- [ ] Pre-launch reportのクラッシュ、ANR、アクセシビリティ、セキュリティ警告を確認する。`Codex・共同`
- [ ] Play Consoleのポリシー警告とAAB警告を解消する。`共同`

### 16.2 Closed testing

- [ ] 新しい個人アカウントのテスト要件対象か再確認する。`ユーザー`
- [ ] 対象の場合、Googleアカウントを持つテスターを最低12人確保する。`ユーザー`
- [ ] クローズドテストの参加リンクと説明を配布する。`ユーザー`
- [ ] 12人以上が14日間連続でオプトイン状態を維持する。`ユーザー`
- [ ] テスターへ実際に主要機能を使ってもらう。`ユーザー`
- [ ] フィードバック、端末、利用期間、修正内容を記録する。`共同`
- [ ] 重大な不具合を修正し、更新版を同じトラックで再確認する。`Codex・共同`
- [ ] 条件達成後、テスト内容と本番準備に関する質問へ回答してProductionアクセスを申請する。`ユーザー・共同`

## 17. 本番前の最終判定

- [ ] Android実機テストのP0がすべて合格している。`共同`
- [ ] P1に公開を妨げる不合格がない。`共同`
- [ ] クラッシュとANRの未解決P0が0件である。`共同`
- [ ] 他ユーザーのデータを閲覧できない。`Codex・共同`

- [ ] 写真・動画アップロード失敗時にデータ不整合がない。`Codex・共同`
- [ ] バックアップからStaging DBを復元できる。`Codex`
- [ ] Privacy policy、Data safety、権限、実装が一致する。`共同`
- [ ] Premium価格とPlay請求画面の価格が一致する。`共同`
- [ ] 審査アカウントと英語のアクセス手順が有効である。`共同`
- [ ] Production AABの開発用機能が無効である。`Codex`
- [ ] Production API、DB、R2、監視が稼働している。`共同`
- [ ] リリースノートを日本語・英語で作成する。`共同`
- [ ] ロールバックまたは公開停止の判断基準を決める。`ユーザー`
- [ ] 最終公開の承認者が承認する。`ユーザー`
